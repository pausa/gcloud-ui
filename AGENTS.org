* Changelog
  
- README.org: documented the suggested stack (Tauri 2 + TypeScript/Solid, gcloud subprocess model) and how to run the project.
- shell.nix: added the required dependencies (rust, node, Tauri Linux build libs) alongside =google-cloud-sdk=.
- Implemented the *Job list view* section: scaffolded the Tauri 2 + Solid project (see README.org for the stack) and added a Cloud Run jobs table backed by =gcloud run jobs list= and =gcloud run jobs executions list=. Features: filter by name, exit code of last run (OK/error badge), name, last run time and duration. Verified with =npm run build= and =cargo check=.
- Job list no longer browses job executions on load; run info (exit code, last run time, duration) is now loaded on demand via a per-row button (=load_job_details= command).
- The last run column now shows the =startTime= of the last execution instead of its completion time.
- Detail fields are initialised from =status.latestCreatedExecution= of the job list response (no extra gcloud call); the per-row button only loads the missing info (e.g. exit code).
- Fix: the v1 =latestCreatedExecution= reference has no =startTime=; the list now reads =creationTimestamp=, =completionTimestamp= and =completionStatus= (which also initialises the exit code).
- Added a dark low-contrast theme inspired by the doom-one Emacs theme (=src/theme.css=).
- Name filter: whitespace-separated tokens are matched independently (order doesn't matter), e.g. =test fetcher= matches =fetcher-customer-test-job=.
